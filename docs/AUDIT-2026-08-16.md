# NIGHTFALLCOIN — Security review of protocol v8 (n8)

**Date:** 2026-08-16
**Scope:** the live 0.7.0 tree — consensus, ledger, P2P, node, desktop wallet,
mobile HTTP + UniFFI apps, browser WASM wallet, website Worker.
**Method:** internal review of the code that is actually running, plus the
v4 exploit suite (`exploit_regression.rs`) re-run against this tree.
**This is not an independent third-party audit.** The same people who
wrote the cryptography wrote this document. Passing tests are not an
outside review. Say that first, or do not publish.

**Verdict:** the v4 inflation class is **closed**. Anyone can still verify
the supply. The new risk is not a tautological balance proof — it is
**light clients that trust a node**, a **browser that stores a seed**, and
a **network that is still small**.

Live chain this review was written against: protocol **8**, wire **6**,
magic `NFL2`, genesis
`061a052d49607ff8f4b306c75d622ebd230cff4ec3a45a6dffc2f7738d4b20de`,
datadir `nightfall/<net>/n8/`. Build 0.7.0.

The v4 write-up stays at [AUDIT-2026-08-12.md](AUDIT-2026-08-12.md). It is
history, not this chain.

## 2. What still holds

### 2.1 Value cannot hide in the books

Every full node checks, after every block and on startup:

```
Σ UTXO  −  Σ kernel excess  =  (minted − burned) · G
```

A kernel is a Schnorr signature over generator `H`. Signing a point that
still has a `G` component means solving the discrete log between `G` and
`H`. That is the statement “this transaction created no money.”

Every output carries a Bulletproof that `v ∈ [0, 2⁶⁴)`. A negative amount
cannot sneak through the commitment.

The six v4 exploits — thin-air mint, negative output, fake input,
malleated auth, rewritten ciphertext, uncapped emit — are inverted in
`exploit_regression.rs`. They fail on this tree.

### 2.2 Addresses never touch the chain

An `nf1…` address is `(scan, spend)`. The sender builds a one-time key
`Ko = B + H("ko" ‖ t)·G` and an ECDH payload. The chain stores `Ko`, the
ephemeral key, a view tag, and the commitment. It never stores the
address.

A view key (`nfview1…`) decrypts amounts and memos and cannot sign. A
receipt proves **one** output: the commitment opens, and the spend key of
the address signs that opening.

### 2.3 Emission is in the header

6 NIGHT per block, halving every 7,500,000 blocks, hard cap 90,000,000.
The curve stops at **89,999,999.25**. Fees burn while a subsidy exists.
After the last reward, fees go to the miner (not minted, not burned).
There is no premine, no admin key, no protocol-level freeze.

### 2.4 What we will not say

Not 100 % anonymous. Not untraceable. Not “protocol-scale anonymity.”
The set is the other transactions in the same block, plus however many
people actually use the chain. A ticker we invented would be a lie.

## 3. Open findings

### I-01 — This document is not an outside audit

The v4 audit, the v5 rewrite, the v8 reset, the mobile FFI, the browser
wallet and this review were produced by the same project. That is a
conflict of interest. It is also why v4 shipped a tautology: the author
believed the proof.

**Until someone else reads the cryptography and publishes their own
write-up, treat every “fixed” row as a claim, not a certificate.**

### H-01 — A young chain can be out-mined

Nighthash-v2 is Argon2id at 32 MiB. That stops a SHA-256 ASIC. It does
not stop a room of CPUs. Cumulative work is the fork rule, so whoever
has more hashes writes history. On a week-old chain that person can be
one operator.

A reorg deeper than coinbase maturity (1,440 blocks, ~6 hours) can
invalidate spends that already looked confirmed. Light clients cannot
see this (L-01).

### L-01 — Light clients believe the node

Argon2id at 32 MiB per header is not something a phone or a browser
does for the whole history. Android, iOS and the PWA ask a node for
`status`, `scan_feed` and `submit_tx`, then scan locally.

A hostile node can:

- hide an output that is yours
- invent an output that is not on the chain
- lie about height and confirmation depth

It **cannot** construct a valid spend. The seed never leaves the device
(or, for the web wallet, the origin). This is a display-integrity
problem, not a theft problem — unless the user acts on a fake payment.

Default node: `seed.nightfallcoin.org:17888`. The settings screen and
the web wallet both say this. Point the app at your own node.

### L-02 — The browser wallet stores the seed in `localStorage`

`website/public/wallet/app.js` writes `nf-web-wallet-v1`. The blob is
JSON with the 32-byte seed as hex (`Wallet::export_state`). Anyone who
can run script on `nightfallcoin.org/wallet/` can read it. That includes
a future XSS, a malicious extension, and a shared computer.

CSP is `script-src 'self' 'wasm-unsafe-eval'` on `/wallet/` and
`script-src 'self'` everywhere else. That is the right shape. It is not
a substitute for paper backup. The 24 words are the real wallet.

### L-03 — The Worker is on the path of every web-wallet request

`POST /wallet-api` is a same-origin proxy onto
`http://seed.nightfallcoin.org/` (port 80 → 17888). Cloudflare and the
Worker see:

- every `scan_feed` range the browser asks for
- every `submit_tx` body (the raw transaction)

The seed never appears in that traffic. The **transaction** does. For a
web-wallet send, the Worker is hop zero. Combine with P-05.

Method allowlist: `status`, `scan_feed`, `submit_tx`, `get_utxo_root`,
`banner`. `mine_one` is rejected. Body cap 512 KiB. That is the same
allowlist as the phone API.

### A-01 — The anonymity set is this block, on this network

Blocks flatten inputs, outputs and kernels and sort them. An observer
does not see “Alice paid Bob.” They see a bag. The bag is only as large
as the number of real transactions in that block. A chain that produces
one coinbase and nothing else has an anonymity set of one.

Do not advertise protocol-scale privacy. The honest line is in
`PRIVACY.md`.

### G-01 — No cut-through

One-sided payments need a per-input signature so the sender cannot
reclaim the output. Cut-through would delete that signature. The graph
of spent commitments therefore remains. Aggregation mixes it. It does
not erase it.

### N-11 — Stem/fluff is not Dandelion++

A new `Tx` goes to one random peer (stem, 12–28 s embargo, 90 % chance
to keep stemming) and then fluffs. The stem uses the same peer set as
blocks. There is no separate stem graph and no fail-safe fluff on a
black-hole stem. A hop onto a node that still broadcasts immediately
is a leak.

### N-12 — Tor falls back

Default proxy is `127.0.0.1:9050`. If Tor is down, the node dials
clearnet and says so. `.onion` never falls back. `NIGHTFALL_PROXY=off`
disables the proxy. A user who thinks they are always on Tor, and is
not, has a smaller privacy set than they were told — unless they read
the status line.

### P-05 — Submit is origin

The first node that accepts `submit_tx` is, with high probability, the
origin of that transaction. On a phone the IP is a person. On the web
wallet the origin is the Worker (L-03) and then the seed. Desktop with
Tor + stem is the less bad case. The send screens say this once.

### D-01 — Unsigned binaries

macOS DMGs, Windows EXEs, the Android APK and the iOS IPA are not
code-signed. Checksums are published
(`SHA256SUMS-0.7.0*.txt`). The site tells people how to open an
unsigned build. A swapped binary on a compromised mirror is caught by
the hash, not by Gatekeeper.

The IPA cannot be tapped to install. AltStore / Sideloadly / Xcode.
A free Apple ID lasts seven days. That is Apple, not us.

### D-02 — One seed

`seed.nightfallcoin.org` is compiled into builds, answers P2P `:17891`,
answers the light API on `:17888`, and is what the Worker fetches on
`:80`. If it lies, every default light client lies with it. If it
goes down, new nodes still find each other only if someone else is
already peered. Run a second seed if you care about this.

### L-04 — Light API is HTTP

No TLS on 17888. Port 80 is a `socat` forward to the same listener,
because Cloudflare Workers cannot `fetch()` :17888. The allowlist is
the protection, not encryption. Anyone on the path reads
`scan_feed` pages (public chain data) and `submit_tx` (P-05). Put
Caddy in front if you run your own node for phones.

### W-05 — `'wasm-unsafe-eval'`

Chromium treats `WebAssembly.instantiate` as eval. The wallet page
allows it. The homepage does not. A script injection on `/wallet/`
could compile WASM. CSP still forbids third-party script. Do not
relax `script-src` further.

### S-01 — 0.75 NIGHT never exists

`2 × 6 × 7,500,000 = 90,000,000`, but integer halvings leave
89,999,999.25 as the terminal minted amount. The cap is a ceiling.
The missing 0.75 is not stealable. It is not in the UTXO set.

### S-02 — Two public geneses in a month

v4 was unsound (2026-08-12). v7 minted almost everything in seven
years. v8 is this chain. Both failures are in `HISTORY.md` and
`RESET.md`. A third silent reset would be worse than a documented
one. Social trust is not a consensus rule and cannot be patched.

| Surface | What it is | What it must not do | What it can do |
|---------|------------|---------------------|----------------|
| `nightfalld --mobile-listen` | HTTP allowlist | Must never expose `mine_one` or wallet RPC | Lie to a scanner (L-01) |
| `nightfall-mobile` UniFFI | Android / iOS FFI | Must not reimplement key derivation | Trusts the node |

| Unsigned IPA / APK | Sideload | Must not claim App Store / Play | User resigns (D-01) |

`mine_one` on `/wallet-api` returns 403. Checked live 2026-08-16.

Safari on iPhone rejected wasm-bindgen `u64` as `BigInt` (“Invalid
argument type in ToBigInt operation”). Heights are JS `Number` (`f64`)
as of this review. That was a liveness bug, not a theft bug.

## 5. What a hostile party still cannot do

Assuming they do not have your seed and do not out-mine the network
(H-01):

- mint NIGHT without a coinbase that pays the schedule
- spend an output they do not own
- put a negative amount in an output that verifies
- spend a commitment that is not in the UTXO set
- freeze or blacklist an address (there is no such opcode)
- read an amount or an `nf1` off the chain
- turn a view key into a spend

They **can** lie to a phone, lie to a browser, watch a web-wallet
submit, and — if they have the hashrate — rewrite recent blocks.

## 6. Recommendations (priority)

1. **Independent review** of `nightfall-crypto` + `nightfall-ledger`
   (I-01). Pay someone who did not write it.
2. **A second seed**, not run by the same operator (D-02).
3. **TLS in front of the light API** (L-04). Leave the allowlist.
4. **Do not keep the seed in `localStorage` forever** (L-02). A
   wrapped key in IndexedDB is still XSS-reachable; the real fix is
   “the 24 words are the wallet” and a desktop/phone app for size.
5. **Do not mine most of the blocks** if you invented the chain
   (H-01 + A-01). A two-miner float is an inventory, not a market.
6. Leave `exploit_regression.rs` alone.
